# 文件传输模块设计

**版本**：v1.0  
**日期**：2026-04-17

---

## 1. 概述

CubicleChat 的文件/图片传输基于 **TCP** 协议，以确保数据完整性。UDP 协议仅用于传输元信息通知。

| 阶段 | 协议 | 说明 |
|------|------|------|
| 传输协商 | UDP | 发送方通过 UDP 发送 `FILE_NOTIFY`，接收方回复 `FILE_ACCEPT`/`FILE_REJECT` |
| 数据传输 | TCP | 实际文件数据通过 TCP 传输，保证可靠性 |

## 2. 传输流程

### 2.1 完整流程图

```
发送方                                    接收方
   │                                         │
   │  1. 用户触发（拖放/选择文件）             │
   │                                         │
   │  2. 读取文件元信息                        │
   │     - 文件名、大小、MD5                   │
   │     - 生成 transferId（UUID）            │
   │                                         │
   │──3. UDP FILE_NOTIFY ──────────────────►│
   │     { transferId, fileName, fileSize,   │
   │       fileMd5, tcpPort, thumbnailData } │
   │                                         │  4. 展示接收请求 UI
   │                                         │     (文件名、大小、发送方)
   │                                         │
   │◄──5. UDP FILE_ACCEPT ──────────────────│
   │     { transferId, offset: 0 }           │  (用户点击接受)
   │                                         │
   │  6. 建立 TCP 监听 (tcpPort)             │
   │     等待接收方连接                        │
   │                                         │
   │                           TCP 连接 ────►│
   │  7. 发送握手包                           │
   │──── HANDSHAKE { transferId, offset } ──►│
   │                                         │  验证 transferId
   │◄─── HANDSHAKE_OK ────────────────────── │
   │                                         │
   │  8. 分块发送                            │
   │──── CHUNK { seq, data[512KB] } ────────►│  写入本地文件
   │──── CHUNK { seq, data[512KB] } ────────►│
   │  ...                                    │
   │──── CHUNK_END { fileMd5 } ─────────────►│
   │                                         │  验证 MD5
   │◄─── TRANSFER_DONE ─────────────────────│
   │                                         │
   │  9. 更新 DB 记录状态=completed          │  更新 DB 记录状态=completed
```

### 2.2 拒绝流程

```
发送方                                    接收方
   │                                         │
   │──── UDP FILE_NOTIFY ───────────────────►│
   │                                         │
   │◄─── UDP FILE_REJECT ───────────────────│
   │     { transferId, reason: "rejected" }  │
   │                                         │
   │  显示"对方拒绝接收文件"通知              │
```

### 2.3 断点续传流程

```
发送方                                    接收方
   │  (重新连接或恢复传输)                    │
   │                                         │
   │──── UDP FILE_NOTIFY ───────────────────►│
   │     { transferId, ... }                 │  检查本地是否有部分文件
   │                                         │  found: partially downloaded 320KB
   │◄─── UDP FILE_ACCEPT ───────────────────│
   │     { transferId, offset: 327680 }      │  (320KB = 327680 字节)
   │                                         │
   │  建立 TCP 连接                           │
   │──── HANDSHAKE { transferId,             │
   │                 offset: 327680 } ──────►│
   │◄─── HANDSHAKE_OK ───────────────────── │
   │                                         │
   │  从 offset 处开始发送剩余数据             │
   │──── CHUNK { seq: 640, data } ──────────►│  以 append 模式写入
   │  ...                                    │
```

## 3. TCP 消息帧格式

所有 TCP 消息使用**长度前缀帧**（Length-Prefixed Frame）：

```
┌──────────────┬────────────────────────────────┐
│  长度(4字节)  │  消息体（JSON 或二进制数据）     │
│  Big-Endian  │  最大 512KB + 8字节头           │
└──────────────┴────────────────────────────────┘
```

**控制消息（JSON）：**
```typescript
interface TcpMessage {
  type: "HANDSHAKE" | "HANDSHAKE_OK" | "CHUNK" | "CHUNK_END" | "TRANSFER_DONE" | "ERROR";
  transferId?: string;
  offset?: number;
  seq?: number;       // chunk 序号（用于排序验证）
  fileMd5?: string;   // CHUNK_END 时携带
  errorCode?: string;
}
```

**数据帧（CHUNK）：**
```
┌──────────────┬─────────────────┬──────────────────────────┐
│  总长度(4B)  │  JSON 头(N字节)  │  二进制数据（文件块）     │
│              │  {"type":"CHUNK",│  最大 524288 字节(512KB) │
│              │   "seq":1,       │                          │
│              │   "headerLen":X} │                          │
└──────────────┴─────────────────┴──────────────────────────┘
```

## 4. 图片处理

### 4.1 图片缩略图

发送图片时，发送方在 **主进程** 中生成缩略图：

```typescript
import sharp from 'sharp';

async function generateThumbnail(filePath: string): Promise<Buffer> {
  return sharp(filePath)
    .resize(240, 240, {
      fit: 'inside',          // 保持比例，不超过 240x240
      withoutEnlargement: true,
    })
    .jpeg({ quality: 75 })
    .toBuffer();
}
```

- 缩略图随 `FILE_NOTIFY` 的 UDP 包以 **Base64** 形式发送（最大 ~32KB）
- 原图通过 TCP 单独传输
- 接收方在消息气泡中立即显示缩略图，原图下载后替换

### 4.2 图片格式支持

| 格式 | 输入 | 输出（存储） |
|------|------|-----------|
| JPEG | ✅ | JPEG（原格式） |
| PNG | ✅ | PNG（原格式） |
| GIF | ✅（静态）| GIF |
| WebP | ✅ | WebP |
| BMP | ✅ | 转换为 PNG |
| TIFF | ✅ | 转换为 JPEG |

### 4.3 剪贴板图片发送

```typescript
// 渲染进程：监听粘贴事件
document.addEventListener('paste', async (e) => {
  const items = e.clipboardData?.items;
  for (const item of items ?? []) {
    if (item.type.startsWith('image/')) {
      const blob = item.getAsFile();
      if (!blob) continue;

      // 临时保存到 temp 目录
      const buffer = await blob.arrayBuffer();
      const tempPath = await window.ipc.send('file:saveTemp', {
        data: Array.from(new Uint8Array(buffer)),
        ext: '.png',
      });

      // 显示预览，等待用户确认发送
      showImagePreview(tempPath);
    }
  }
});
```

## 5. 传输性能优化

### 5.1 并发限制

```typescript
// 同时最多 3 个文件传输（发送+接收各 3 个）
const MAX_CONCURRENT_TRANSFERS = 3;

class TransferQueue {
  private queue: TransferTask[] = [];
  private active: Map<string, TransferTask> = new Map();

  enqueue(task: TransferTask) {
    if (this.active.size < MAX_CONCURRENT_TRANSFERS) {
      this.startTransfer(task);
    } else {
      this.queue.push(task);
    }
  }

  private onTransferComplete(transferId: string) {
    this.active.delete(transferId);
    const next = this.queue.shift();
    if (next) this.startTransfer(next);
  }
}
```

### 5.2 分块大小策略

| 文件大小 | 分块大小 | 原因 |
|---------|---------|------|
| < 1MB | 128 KB | 小文件快速传输 |
| 1MB - 100MB | 512 KB | 平衡内存与吞吐 |
| > 100MB | 1 MB | 减少 IPC 开销 |

### 5.3 速度限制（可选）

用户可在设置中配置传输速度上限，避免影响其他网络活动：

```typescript
class ThrottledStream extends Transform {
  private bytesPerSecond: number;
  private bytesSent: number = 0;
  private windowStart: number = Date.now();

  _transform(chunk: Buffer, _encoding: string, callback: Function) {
    const now = Date.now();
    const elapsed = now - this.windowStart;

    if (elapsed >= 1000) {
      // 新的时间窗口，重置计数
      this.bytesSent = 0;
      this.windowStart = now;
    }

    if (this.bytesSent + chunk.length > this.bytesPerSecond) {
      // 需要限速，延迟发送
      const delay = 1000 - elapsed;
      setTimeout(() => {
        this.push(chunk);
        this.bytesSent += chunk.length;
        callback();
      }, delay);
    } else {
      this.push(chunk);
      this.bytesSent += chunk.length;
      callback();
    }
  }
}
```

## 6. 安全与校验

### 6.1 文件完整性验证

```typescript
import { createHash } from 'crypto';
import { createReadStream } from 'fs';

async function calculateMd5(filePath: string): Promise<string> {
  return new Promise((resolve, reject) => {
    const hash = createHash('md5');
    const stream = createReadStream(filePath);
    stream.on('data', chunk => hash.update(chunk));
    stream.on('end', () => resolve(hash.digest('hex')));
    stream.on('error', reject);
  });
}

// 传输完成后验证
async function verifyTransfer(localPath: string, expectedMd5: string): Promise<boolean> {
  const actualMd5 = await calculateMd5(localPath);
  return actualMd5 === expectedMd5;
}
```

### 6.2 恶意文件防护

```typescript
const BLOCKED_EXTENSIONS = [
  '.exe', '.msi', '.bat', '.cmd', '.ps1', '.sh',
  '.vbs', '.js', '.jar', '.scr', '.pif',
];

// 接收方检查（可在设置中禁用）
function isSafeFile(fileName: string): boolean {
  const ext = path.extname(fileName).toLowerCase();
  return !BLOCKED_EXTENSIONS.includes(ext);
}
```

> 注意：v1.0 仅显示警告，不强制阻止（用户可选择是否接收）。

### 6.3 路径穿越防护

```typescript
function getSafeSavePath(downloadDir: string, fileName: string): string {
  // 清理文件名，防止路径穿越（../../../etc/passwd）
  const safeName = path.basename(fileName).replace(/[\\/:*?"<>|]/g, '_');
  const fullPath = path.join(downloadDir, safeName);

  // 确保目标路径在下载目录内
  if (!fullPath.startsWith(downloadDir)) {
    throw new Error('Invalid file path');
  }

  return fullPath;
}
```

## 8. 错误处理

| 错误场景 | 处理策略 |
|---------|---------|
| 接收方 TCP 端口被占用 | 自动尝试 2426-2430，超出范围提示用户 |
| 传输超时（60s 无数据） | 标记失败，显示"续传"按钮 |
| MD5 校验失败 | 自动触发从断点重新传输（最多重试 2 次） |
| 磁盘空间不足 | 传输前检查，不足时通知用户并拒绝接收 |
| 对方突然离线 | 暂停传输，等待对方重新上线后可续传 |
| 文件被删除（传输中） | 发送方报错，告知接收方"文件已不可用" |

---

*文件传输模块是 CubicleChat 的核心功能，实现时需优先保障数据完整性和断点续传的可靠性。*
