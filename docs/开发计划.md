# 开发计划与里程碑

**版本**：v1.0  
**日期**：2026-04-17

---

## 1. 总体规划

CubicleChat v1.0 采用**迭代式开发**，分为 4 个阶段（Sprint），每个 Sprint 约 2 周。

```
Sprint 1        Sprint 2        Sprint 3        Sprint 4
[基础框架]  →   [核心功能]  →   [高级功能]  →   [打磨发布]
Week 1-2        Week 3-4        Week 5-6        Week 7-8
```

## 4. 技术风险与缓解措施

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| UDP 广播被防火墙拦截 | 中 | 高 | 提供手动添加 IP 的点对点模式 |
| 多平台 better-sqlite3 构建问题 | 中 | 中 | 使用 electron-rebuild 预构建原生模块 |
| Linux 系统通知兼容性 | 低 | 低 | 降级到任务栏图标闪烁 |
| 大文件（>1GB）传输内存溢出 | 低 | 高 | 全程使用 Node.js Stream，避免加载到内存 |
| 并发传输时 TCP 端口冲突 | 低 | 中 | 动态端口分配（2426-2499 范围内） |

## 6. 开发规范

### 6.1 提交规范（Conventional Commits）

```
feat(network): 实现 UDP 用户发现广播机制
fix(db): 修复消息撤回后内容未清空的问题
docs(udp): 补充心跳超时状态机说明
test(file): 添加大文件 MD5 校验测试
chore(build): 升级 electron-builder 至 24.13.3
```

### 6.2 分支策略

```
main          - 稳定发布分支
develop       - 开发主分支
feature/xxx   - 功能分支（从 develop 切出）
fix/xxx       - 修复分支
```

### 6.3 代码审查清单

- [ ] 是否有未处理的 Promise rejection？
- [ ] IPC Handler 是否做了参数验证？
- [ ] 是否有内存泄漏风险（事件监听未清理）？
- [ ] 数据库操作是否在主进程执行（而非渲染进程）？
- [ ] 是否在主进程中直接操作文件系统（而非渲染进程）？
