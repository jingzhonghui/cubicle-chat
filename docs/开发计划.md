## 1. 概览

### 1.1 总体目标

交付一款面向局域网的跨平台即时通讯工具，实现：
- 同局域网用户自动发现
- 即时文本消息收发
- 文件/图片传输
- 群聊功能
- 消息历史存储

### 1.2 里程碑

| 里程碑 | 时间节点 | 核心交付物 |
|--------|---------|-----------|
| **M1 可运行原型** | Week 2 | 项目框架 + 用户发现 + 单聊 |
| **M2 核心功能** | Week 4 | ACK/撤回 + 图片/文件传输 + 持久化 |
| **M3 高级功能** | Week 6 | 群聊 + 搜索 + 断点续传 + 主题 |
| **M4 发布就绪** | Week 8 | 三平台打包 + 测试修复 + 文档 |

### 1.3 技术栈

| 类别 | 技术 |
|------|------|
| 框架 | Electron 29 + React 18 |
| 语言 | TypeScript 5 |
| 样式 | Tailwind CSS v3 |
| 状态 | Zustand |
| 数据库 | better-sqlite3 + Drizzle ORM |
| 构建 | Vite + electron-vite |
| 打包 | electron-builder |

## 3. Sprint 详细计划

### Sprint 1：基础框架

**周期**：Week 1 - Week 2（10 天）  
**目标**：搭建可运行的项目框架，实现用户自动发现

#### 3.1.1 任务分解

| # | 任务 | 优先级 | 估时 | 负责人 | 验收标准 |
|---|------|--------|------|--------|---------|
| 1.1 | 项目初始化：electron-vite + React + TypeScript + Tailwind | P0 | 0.5d | - | `npm run dev` 能启动，页面显示空白壳 |
| 1.2 | 配置 electron-builder（Windows/macOS/Linux） | P0 | 0.5d | - | `npm run build` 生成各平台安装包 |
| 1.3 | 自定义标题栏 + 三栏布局框架 | P0 | 2d | - | 导航栏(48px) + 会话列表(240px) + 聊天区(flex) |
| 1.4 | 配置 Zustand store 结构 | P1 | 0.5d | - | 创建 userStore, messageStore, settingsStore 骨架 |
| 1.5 | 配置 better-sqlite3 + Drizzle + Schema 定义 | P0 | 2d | - | 建表脚本可执行，users/conversations/messages/files/settings 表存在 |
| 1.6 | UDP Socket 绑定 + 广播发送/接收 | P0 | 2d | - | 发送 ONLINE 包到 255.255.255.255:2425，能收到局域网其他用户 |

| 1.8 | 联系人列表 UI + 在线状态显示 | P1 | 1d | - | 左侧列表显示用户昵称 + 状态点（绿/黄/灰） |

#### 3.1.2 完成标准

- [ ] 项目可 `npm run dev` 启动

### Sprint 2：核心聊天功能

**周期**：Week 3 - Week 4（10 天）  
**目标**：实现完整的消息收发功能

#### 3.2.1 任务分解

| # | 任务 | 优先级 | 估时 | 验收标准 |
|---|------|--------|------|---------|
| 2.1 | UDP 文本消息发送/接收 + ACK 重试 | P0 | 2d | 发送消息后收到对方 ACK，3次失败显示红色感叹号 |
| 2.2 | 消息去重（LUR Cache）+ 持久化 SQLite | P0 | 1.5d | 重启后消息历史可加载，不重复显示 |
| 2.3 | 消息气泡 UI + 虚拟滚动（react-window） | P0 | 3d | 消息列表 >100 条无卡顿，头像/昵称/时间正确 |
| 2.4 | 消息状态指示（发送中/已发送/送达）+ 撤回 | P1 | 2d | 消息旁显示 ✓ / ✓✓ / 感叹号，2分钟内可撤回 |
| 2.5 | 输入框 + Emoji 面板 + Enter 发送 | P1 | 2d | Shift+Enter 换行，粘贴截图直接发送 |
| 2.6 | 图片发送：选择/拖放/粘贴 + 缩略图生成 | P0 | 2.5d | 发送 PNG/JPG/GIF，最大 20MB，显示 240px 缩略图 |

| 2.8 | 系统托盘 + 桌面通知 + 未读角标 | P1 | 2d | 最小化到托盘，新消息弹通知，有未读显示红点 |
| 2.9 | 个人设置面板（昵称/头像/状态） | P1 | 1.5d | 修改后广播状态变更，对方 30 秒内更新 |

#### 3.2.2 完成标准

- [ ] 单聊文本消息 < 100ms 延迟

## 6. 风险与应对

### 6.1 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| UDP 广播被防火墙拦截 | 中 | 高 | 提供手动添加 IP 的点对点模式 |
| better-sqlite3 原生模块构建问题 | 中 | 中 | electron-rebuild 预构建 |
| 大文件传输内存溢出 | 低 | 高 | 全程 Stream，避免加载到内存 |
| 并发 TCP 端口冲突 | 低 | 中 | 动态端口分配（2426-2499） |

### 6.2 进度风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| Sprint 1 延期 | 低 | 高 | 预留 1 天 buffer |
| 跨平台兼容问题 | 中 | 中 | 每周进行多平台构建测试 |
| 测试发现问题过多 | 中 | 中 | Bug 修复单独分配 3 天 |

### 6.3 质量风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| 内存泄漏 | 中 | 中 | 每周做内存 profiling |
| 消息丢失 | 低 | 高 | ACK + 重试机制 |
| 数据损坏 | 低 | 高 | SQLite WAL 模式 |
