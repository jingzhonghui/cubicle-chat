## 1. 技术选型

### 1.1 技术栈

| 层次 | 候选方案 | 选定方案 | 选定理由 |
|------|---------|---------|---------|
| 应用框架 | Electron / Tauri / Qt | **Electron 29** | 跨平台成熟度最高，生态最丰富，Web 技术栈开发效率高 |

### 2.2 三层服务架构

```
IPC Handler → Service → Repository → Database
     ↕                                  ↕
  网络事件                            SQLite
```

| 层次 | 职责 | 禁止事项 |
|------|------|---------|
| IPC Handler | 参数校验、调用 Service、格式化响应 | 包含业务逻辑 |
| Service | 业务规则、编排多个 Repository 调用 | 直接访问数据库 |
| Repository | SQL 查询、数据映射 | 包含业务逻辑 |

### 4.1 技术方案

- **引擎**：SQLite（better-sqlite3）
- **ORM**：Drizzle ORM
- **日志模式**：WAL（Write-Ahead Logging）
- **全文搜索**：SQLite FTS5

### 4.2 数据库配置

```typescript
sqlite.pragma('journal_mode = WAL');       // WAL 模式

sqlite.pragma('foreign_keys = ON');        // 外键约束
```

### 4.5 索引设计

```sql
-- 用户
CREATE INDEX idx_users_ip ON users(ip_address);
CREATE INDEX idx_users_status ON users(status);

-- 会话
CREATE INDEX idx_conversations_target ON conversations(target_id);
CREATE INDEX idx_conversations_last_msg ON conversations(last_message_at DESC);

-- 消息
CREATE INDEX idx_messages_conversation ON messages(conversation_id, sent_at DESC);
CREATE INDEX idx_messages_sender ON messages(sender_id);
CREATE INDEX idx_messages_file ON messages(file_id);

-- 全文搜索（FTS5）
CREATE VIRTUAL TABLE messages_fts USING fts5(
  message_id UNINDEXED,
  content,
  content='messages',
  content_rowid='rowid'
);

-- FTS 同步触发器
CREATE TRIGGER messages_fts_insert AFTER INSERT ON messages BEGIN
  INSERT INTO messages_fts(rowid, message_id, content)
  VALUES (new.rowid, new.message_id, new.content);
END;
```

### 4.6 数据清理策略

每天凌晨 3:00（或应用启动时检查）自动执行：
1. 删除超过保留天数的旧消息
2. 删除已完成的旧文件传输记录（实际文件不删除）
3. 执行 `VACUUM` 压缩数据库

## 5. 网络协议设计

### 5.1 协议选型

| 协议 | 用途 | 端口 | 说明 |
|------|------|------|------|
| **UDP** | 用户发现广播、即时消息 | 2425 | 与飞秋（FeiQ）同端口 |
| **TCP** | 文件/图片可靠传输 | 2426 | 保证数据完整性 |

### 5.2 用户发现机制

采用 **UDP 广播 + 心跳** 模式：

```
应用启动
    │
    ├─ 绑定 UDP 0.0.0.0:2425
    ├─ 监听所有 IPv4 接口的广播
    └─ 发送 ONLINE 广播包 → 255.255.255.255:2425
         │
         ▼
    局域网内所有用户收到广播
         └─ 每个收到广播的用户回复 ONLINE_ACK 单播包

定时任务：每 30 秒发送 HEARTBEAT 广播
    └─ 超过 90 秒未收到 HEARTBEAT → 标记用户离线
```

### 5.3 UDP 数据包格式

所有 UDP 数据包使用 **JSON** 编码（UTF-8）：

```typescript
interface UdpPacket {
  magic: "CCHT";            // 魔数，过滤无关广播包
  version: 1;               // 协议版本
  type: PacketType;         // 包类型
  msgId: string;            // UUID，用于去重/ACK
  timestamp: number;        // Unix timestamp（毫秒）

  from: {
    userId: string;         // UUID（本机生成，持久化）
    nickname: string;       // 显示名称
    ip: string;             // 发送方 IP
    port: number;           // TCP 文件传输端口（2426）
    avatar?: string;        // Base64 缩略头像（64×64 JPEG）
    status: UserStatus;     // 'online' | 'busy' | 'away'
    version: string;        // 客户端版本号
  };

  payload?: Record<string, unknown>;
}

type PacketType =
  | "ONLINE"          // 上线广播
  | "ONLINE_ACK"      // 上线回复
  | "HEARTBEAT"       // 心跳广播
  | "OFFLINE"         // 主动下线
  | "TEXT"            // 文本消息
  | "TEXT_ACK"        // 消息已接收确认
  | "WITHDRAW"        // 撤回消息
  | "FILE_NOTIFY"     // 文件传输通知
  | "FILE_ACCEPT"     // 接受文件（自动）
  | "GROUP_CREATE"    // 创建群组
  | "GROUP_MESSAGE"   // 群消息
  | "GROUP_LEAVE"     // 离开群组
  | "TYPING"          // 正在输入...
  | "STATUS_CHANGE";  // 状态变更
```

### 5.4 Payload 定义

| type | payload 字段 | 说明 |
|------|-------------|------|
| TEXT | `{to, content, contentType, replyTo?}` | 单聊/群聊文本消息 |
| TEXT_ACK | `{ackMsgId}` | 消息确认 |
| WITHDRAW | `{targetMsgId, to}` | 撤回消息 |
| FILE_NOTIFY | `{to, transferId, fileName, fileSize, fileType, fileMd5, isImage, tcpPort, thumbnailData?}` | 文件传输通知（自动接受） |
| FILE_ACCEPT | `{transferId, tcpPort}` | 自动接受确认（返回接收方TCP端口） |
| TYPING | `{to, isTyping}` | 正在输入提示 |
| GROUP_CREATE | `{groupId, groupName, memberIds[]}` | 创建群组 |
| GROUP_MESSAGE | `{to: groupId, content, contentType}` | 群消息 |

### 5.5 消息可靠性

UDP 不保证投递，应用层实现 ACK + 超时重试：

| 参数 | 值 |
|------|------|
| 最大重试次数 | 3 |
| 初始延迟 | 500 ms |
| 退避倍数 | 2× |
| 重试间隔 | 500ms → 1000ms → 2000ms |
| 3 次失败后 | 标记"发送失败"，显示红色感叹号 + 重试按钮 |

**消息去重**：使用 LRU Cache 缓存最近 1000 条已处理 msgId，丢弃重复包。

## 6. 文件传输模块

### 6.1 传输协议

| 阶段 | 协议 | 说明 |
|------|------|------|
| 传输协商 | UDP | FILE_NOTIFY → FILE_ACCEPT（自动） |
| 数据传输 | TCP | 分块传输，保证可靠性 |

### 6.2 完整传输流程（自动接受）

```
发送方                                    接收方
   │
   │  1. 读取文件元信息（名称、大小、MD5）
   │     图片则生成缩略图（sharp 240×240）
   │
   │──2. UDP FILE_NOTIFY ─────────────────►│
   │     { transferId, fileName, fileSize,   │
   │       fileMd5, tcpPort, thumbnailData } │
   │                                         │  3. 自动创建会话和消息记录
   │                                         │     自动回复 FILE_ACCEPT
   │◄──4. UDP FILE_ACCEPT ──────────────────│
   │     { transferId, tcpPort }             │
   │
   │  5. 建立 TCP 连接
   │                           TCP 连接 ────►│
   │──── HANDSHAKE { transferId, offset } ──►│  验证 transferId
   │◄─── HANDSHAKE_OK ─────────────────────  │
   │
   │  6. 分块发送
   │──── CHUNK { seq, data[512KB] } ───────►│  写入本地文件
   │──── CHUNK_END { fileMd5 } ─────────────►│  验证 MD5
   │◄─── TRANSFER_DONE ─────────────────────│
   │
   │  7. 双方更新 DB 状态 = completed
   │     显示绿色完成进度条
```

**说明**：
- 图片和文件均自动接受，无需用户确认
- FILE_ACCEPT 由接收方自动回复，无需用户干预
- 发送前无需等待，直接发送 FILE_NOTIFY 后开始传输
- 传输进度通过渐变色进度条实时显示

### 6.3 TCP 消息帧格式

所有 TCP 消息使用 **长度前缀帧**（Length-Prefixed Frame）：

```
┌──────────────┬────────────────────────────────┐
│  长度(4字节) │  消息体（JSON 或二进制数据）     │
│  Big-Endian │  最大 512KB + 8字节头            │
└──────────────┴────────────────────────────────┘
```

### 6.4 分块大小策略

| 文件大小 | 分块大小 | 原因 |
|---------|---------|------|
| < 1 MB | 128 KB | 小文件快速传输 |
| 1 - 100 MB | 512 KB | 平衡内存与吞吐 |
| > 100 MB | 1 MB | 减少 IPC 开销 |

### 6.5 传输进度显示

| 状态 | 进度条样式 | 说明 |
|------|-----------|------|
| 等待发送 | 0% 绿色渐变 | `linear-gradient(90deg, #10b981, #34d399, #6ee7b7)` |
| 传输中 | 动态绿色渐变 + 发光效果 | 显示百分比和速度 |
| 已完成 | 100% 绿色渐变 + ✓ 标记 | `box-shadow: 0 0 4px rgba(16, 185, 129, 0.5)` |
| 失败 | 100% 红色渐变 + ✗ 标记 | `linear-gradient(90deg, #ef4444, #f87171, #fca5a5)` |

### 6.6 安全校验

| 机制 | 说明 |
|------|------|
| MD5 校验 | 传输完成后比对 fileMd5，失败自动重试（最多 2 次） |
| 危险扩展名 | .exe/.msi/.bat/.cmd/.ps1 等显示警告 |
| 路径穿越防护 | `path.basename()` 清理文件名 |
| 磁盘空间检查 | 传输前检查可用空间，不足时拒绝接收 |

## 8. IPC接口设计

### 8.1 IPC Channel 规范

| Channel | 方向 | 描述 | 参数 |
|---------|------|------|------|
| `msg:send` | 渲染→主 | 发送消息 | `{to, content, contentType, replyTo?}` |
| `msg:receive` | 主→渲染 | 收到新消息 | 消息对象 |
| `msg:withdraw` | 渲染→主 | 撤回消息 | `{messageId, conversationId}` |
| `msg:search` | 渲染→主 | 搜索历史 | `{keyword, conversationId?}` |
| `msg:history` | 渲染→主 | 加载历史 | `{conversationId, limit, before?}` |
| `user:online` | 主→渲染 | 用户上线通知 | 用户对象 |
| `user:offline` | 主→渲染 | 用户离线通知 | `{userId}` |
| `user:list` | 渲染→主 | 获取在线用户 | `void` |
| `user:update` | 渲染→主 | 更新个人信息 | `{nickname?, avatar?, status?}` |
| `file:send` | 渲染→主 | 发起文件传输（自动接受） | `{to, filePath}` |
| `file:progress` | 主→渲染 | 传输进度 | `{transferId, percent, speed}` |
| `file:complete` | 主→渲染 | 传输完成/失败 | `FileTransfer` |
| `file:list` | 渲染→主 | 获取文件列表 | `{filter?, sort?}` |
| `file:open` | 渲染→主 | 打开文件 | `{fileId}` |
| `file:openFolder` | 渲染→主 | 打开文件所在文件夹 | `{filePath}` |
| `file:select` | 渲染→主 | 选择文件对话框 | `void` |
| `file:get` | 渲染→主 | 获取单个文件信息 | `{fileId}` |
| `file:getPath` | 渲染→主 | 获取文件绝对路径（用于拖拽/粘贴） | `File` → `string` |

**注意**：`file:accept` 和 `file:reject` 已被移除，文件传输改为自动接受模式
| `group:create` | 渲染→主 | 创建群组 | `{groupName, memberIds[]}` |
| `group:invite` | 渲染→主 | 邀请成员 | `{groupId, userIds[]}` |
| `settings:get` | 渲染→主 | 读取设置 | `{key?}` |
| `settings:set` | 渲染→主 | 保存设置 | `{key, value}` |
| `typing:receive` | 主→渲染 | 对方正在输入 | `{from, to}` |

### 9.2 Preload 安全边界

```typescript
contextBridge.exposeInMainWorld('ipc', {
  send: (channel: string, data: unknown) => {
    const allowed = ['msg:send', 'file:send', 'settings:set', ...];
    if (allowed.includes(channel)) ipcRenderer.invoke(channel, data);
  },
  on: (channel: string, callback: Function) => {
    const allowed = ['msg:receive', 'user:online', 'file:progress', ...];
    if (allowed.includes(channel)) {
      ipcRenderer.on(channel, (_, ...args) => callback(...args));
    }
  },
});
```

### 9.3 安全措施总结

| 层面 | 措施 | 版本 |

| 文件传输 | MD5 完整性校验、路径穿越防护、危险扩展名警告 | v1.0 |
