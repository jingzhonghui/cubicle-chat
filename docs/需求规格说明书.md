## 1. 项目概述

CubicleChat 是一款面向企业内网/局域网环境的即时通讯工具，无需服务器部署、无需互联网，开箱即用。用户只需在同一 Wi-Fi 或有线局域网内，即可自动发现彼此并开始通讯。

### 1.1 设计原则

- **零服务器依赖**：所有通信在局域网内点对点完成，无中心节点
- **轻量快速**：安装包 < 80 MB，启动时间 < 2 秒
- **数据本地存储**：所有历史消息与文件元数据存储于本机 SQLite
- **跨平台一致性**：Windows 10+、Linux（Ubuntu 20.04+）界面与体验一致

### 1.2 目标用户

| 用户类型 | 场景 |
|---------|------|
| 小型办公团队 | 日常工作沟通，替代微信/钉钉等需要互联网的工具 |
| 工厂/制造业 | 封闭内网环境下的跨部门沟通 |
| 学校/实验室 | 局域网内文件共享与即时沟通 |
| 保密要求高的单位 | 数据不出内网，合规要求满足 |

## 2. 功能需求

### 2.1 用户发现与管理

#### F-01 局域网自动发现
- **描述**：程序启动后，自动向局域网广播"上线"信号，同时监听其他用户的广播
- **触发条件**：应用启动时、网络接口变更时
- **广播周期**：每 30 秒发送一次心跳广播
- **下线检测**：超过 90 秒未收到心跳，标记用户为离线
- **验收标准**：同局域网内的用户在 10 秒内出现在在线列表中

#### F-02 用户信息设置
- **描述**：用户可设置昵称、头像（可选）
- **昵称**：必填，长度 2-20 字符，默认值为主机名
- **头像**：可选，支持 PNG/JPG，自动裁剪为 64×64 像素，通过 UDP 广播同步
- **验收标准**：更改昵称后，其他在线用户在 30 秒内看到更新

#### F-03 在线状态显示
- 状态列表：在线（绿）、忙碌（黄）、离开（灰）、隐身（对外显示离线）
- 状态可手动切换，不影响消息接收能力（除隐身外）

#### F-04 用户分组
- 支持将用户加入自定义分组（如：研发组、运营组）
- 分组数据存储于本地 SQLite，不同步至其他用户

---

### 2.2 即时消息

#### F-05 单聊（一对一）
- **文本消息**：支持 UTF-8 全字符，单条最大 4096 字节
- **表情**：支持 Unicode Emoji，内置 40 个常用表情面板
- **消息撤回**：发送后 2 分钟内可撤回，对方显示"[消息已撤回]"
- **验收标准**：消息延迟 < 100ms（同局域网）

#### F-06 群聊
- **创建群组**：选择在线用户创建临时群组，群组信息广播通知成员
- **成员管理**：创建者可添加/移除成员
- **群消息**：支持文本、表情、文件（与单聊一致）
- **群组持久化**：群组信息存储在创建者本机，成员重启后通过重新广播恢复
- **最大成员数**：50 人

#### F-07 消息通知
- 新消息时任务栏图标闪烁（Windows）/ 桌面通知（Linux）
- 系统通知包含：发送者昵称 + 消息前 30 字符
- 支持免打扰模式（按会话/全局）

#### F-08 历史消息
- 所有消息存储于本机 SQLite
- 支持按关键词搜索历史消息
- 历史消息默认保留 180 天，可在设置中修改（30-∞天）

---

### 2.3 文件与图片传输

#### F-09 图片发送
- **发送方式**：粘贴剪贴板图片、拖放图片文件、点击按钮选择
- **预览**：消息气泡中内嵌缩略图（最大 240×240 px）
- **原图查看**：点击缩略图在内置查看器中打开原图
- **格式**：PNG、JPG、GIF、WebP，单张最大 20 MB
- **传输协议**：TCP（见文件传输模块）

#### F-10 文件发送
- **拖放发送**：将文件拖入聊天区域触发发送
- **进度显示**：进度条显示传输百分比和速度（KB/s 或 MB/s）
- **断点续传**：传输中断后可从断点继续
- **大小限制**：单文件最大 2 GB
- **传输协议**：TCP，分块大小 512 KB
- **接收确认**：接收方选择保存路径后开始传输；可拒绝接收

#### F-11 文件管理
- 已收/已发文件在"文件"面板中集中展示
- 支持按时间、大小排序
- 支持在本机文件管理器中打开文件所在目录

### 2.4 设置与配置

#### F-12 应用设置
| 设置项 | 类型 | 默认值 | 说明 |
|-------|------|--------|------|
| 我的昵称 | 文本 | 主机名 | - |
| 头像 | 图片 | 默认图标 | - |
| 文件接收目录 | 路径 | ~/Downloads/CubicleChat | - |
| 历史消息保留天数 | 数值 | 180 | 30~无限 |
| 开机自启 | 布尔 | true | 仅 Windows |
| 最小化到托盘 | 布尔 | true | - |
| 语言 | 枚举 | 简体中文 | 简体中文/English |
| UDP 广播端口 | 数值 | 2425 | 与飞秋兼容 |
| TCP 文件传输端口 | 数值 | 2426 | - |

#### F-13 数据管理
- 清空历史消息（按对话/全部）
- 导出聊天记录（JSON / TXT 格式）
- 数据库压缩（VACUUM）

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 要求 |
|------|------|
| 消息发送延迟 | < 100 ms（局域网 1Gbps 环境） |
| 应用启动时间 | < 2 秒（冷启动） |
| 内存占用 | 空闲时 < 80 MB |
| CPU 占用 | 空闲时 < 1%，消息处理时 < 5% |
| 文件传输速度 | 不低于网络带宽的 80% |
| 最大在线用户 | 支持同局域网 200 个用户并发在线 |

### 3.2 可靠性需求

| 指标 | 要求 |
|------|------|
| 消息可靠投递 | 单聊消息有确认机制，超时重试 3 次 |
| 数据不丢失 | SQLite WAL 模式，写入即持久化 |
| 异常恢复 | 崩溃后重启自动恢复所有会话状态 |

### 3.3 兼容性需求

| 平台 | 最低版本 |
|------|---------|
| Windows | Windows 10 (1903+) x64 |
| Linux | Ubuntu 20.04 / CentOS 8 / Debian 11 x64 |
| 网络 | IPv4 局域网，支持 Wi-Fi 和有线以太网 |

### 3.4 安全需求

- **传输加密**：文件传输通过 TCP 支持可选 TLS（v1.0 暂不强制）
- **消息加密**：v1.0 不加密（局域网场景），v1.1 规划 AES-256 加密
- **本地数据**：SQLite 数据库不加密（v1.0），后续支持 SQLCipher

### 3.5 可访问性需求

- 支持键盘快捷键（常用操作 100% 可键盘完成）
- 字体大小可调（小/中/大）
- 高对比度主题（适配系统高对比度模式）

## 4. 用户故事

### Epic 1: 快速上手

```
As 新用户
I want to 启动程序后立即看到局域网内的其他用户
So that 无需任何配置即可开始聊天
```

**验收标准（AC）：**
- AC1: 首次启动后 10 秒内在线列表自动填充（若有其他在线用户）
- AC2: 不需要注册账号、不需要输入服务器地址
- AC3: 默认昵称自动设置为主机名，可随时更改

---

### Epic 2: 日常沟通

```
As 团队成员
I want to 快速发送文本消息和图片给同事
So that 替代微信等需要翻墙或泄露隐私的工具
```

**验收标准（AC）：**
- AC1: Enter 发送消息，Shift+Enter 换行

- AC3: 群消息历史可本地搜索

## 5. 约束与假设

### 5.1 约束

1. **网络环境**：用户必须在同一局域网子网（或通过路由器能互通的网段）内
2. **单点**：v1.0 不支持离线消息——发送消息时接收方必须在线
3. **无服务器**：不依赖任何云服务或中心服务器

### 5.2 假设

1. 局域网内 UDP 广播不被防火墙或交换机阻断
2. 用户设备时钟误差不超过 60 秒（用于消息排序）
3. 同一台机器同时只运行一个 CubicleChat 实例
