# CubicleChat 代码结构文档

## 1. 项目概述

**CubicleChat** 是一个基于 Electron + React 的局域网即时通讯工具，支持：

- UDP 广播自动发现局域网内用户
- 点对点文字消息收发
- **文件/图片传输（TCP 分块传输 + 进度显示 + MD5 校验）**
- 消息状态（发送中/已发送/已送达）
- 消息撤回
- 消息历史本地存储
- 系统托盘运行
- 本地 SQLite 数据存储

### 技术栈

| 类别 | 技术 |
|------|------|
| 桌面框架 | Electron 29 |
| 前端框架 | React 18 + TypeScript 5 |
| 状态管理 | Zustand 4 |
| 样式方案 | Tailwind CSS 3 + CSS 变量 |
| 构建工具 | electron-vite 2 |
| 数据库 | better-sqlite3 |
| 日志 | electron-log 5 |
| 打包工具 | electron-builder |

#### `src/main/network/NetworkService.ts` - UDP 网络服务

**职责**：
- UDP 广播发现局域网用户
- 发送心跳维持在线状态
- 收发消息（文本、撤回、ACK）
- 用户状态同步
- 自动创建会话和保存消息

**常量配置**：
```typescript
const UDP_PORT = 2425             // UDP 广播端口（用户发现/消息/文件协商）
const TCP_PORT_START = 2426       // TCP 端口起始（文件传输）
const TCP_PORT_END = 2499         // TCP 端口结束（动态分配）
const CHUNK_SIZE_SMALL = 128 * 1024   // < 1MB 文件分块大小
const CHUNK_SIZE_MEDIUM = 512 * 1024  // 1-100MB 文件分块大小
const CHUNK_SIZE_LARGE = 1024 * 1024  // > 100MB 文件分块大小
const HEARTBEAT_INTERVAL = 30000  // 心跳间隔（30秒）
const HEARTBEAT_TIMEOUT = 90000   // 心跳超时（90秒）
const MAGIC = 'CCHT'              // 协议魔数
const VERSION = 1                 // 协议版本
```

**数据包类型（PacketType）**：
| 类型 | 说明 |
|------|------|
| `ONLINE` | 上线广播 |
| `ONLINE_ACK` | 上线响应 |
| `HEARTBEAT` | 心跳保活 |
| `OFFLINE` | 下线通知 |
| `TEXT` | 文本消息 |
| `TEXT_ACK` | 消息送达确认 |
| `WITHDRAW` | 消息撤回 |
| `FILE_NOTIFY` | 文件传输通知（发送方→接收方） |
| `FILE_ACCEPT` | 自动接受确认（接收方→发送方，含TCP端口） |
| `STATUS_CHANGE` | 状态变更 |
| `TYPING` | 正在输入 |

**UdpPacket 数据包结构**：
```typescript
interface UdpPacket {
  magic: 'CCHT'      // 魔数验证
  version: number    // 协议版本
  type: PacketType   // 消息类型
  msgId: string      // 消息唯一ID
  timestamp: number  // 时间戳
  from: {
    userId: string
    nickname: string
    ip: string
    port: number
    avatar?: string
    status: UserStatus
    version: string
  }
  payload?: Record<string, unknown>  // 负载数据
}
```

**公开方法**：
- `init()` - 初始化 UDP Socket、TCP 服务、启动心跳
- `getOnlineUsers()` - 获取在线用户列表
- `sendMessage(data)` - 发送消息（同时保存到本地数据库）
- `sendFile(to, filePath)` - 发送文件（UDP 协商 + TCP 传输）
- `withdrawMessage(messageId, conversationId)` - 撤回消息
- `updateStatus(status)` - 更新在线状态
- `sendTyping(to, isTyping)` - 发送正在输入状态
- `sendOffline()` - 发送下线通知
- `destroy()` - 清理资源
- `getNetworkInterfaces(includeVirtual?)` - 获取所有可用的网络接口列表，`includeVirtual` 控制是否包含虚拟网卡（默认 false）
- `getCurrentInterface()` - 获取当前使用的网络接口
- `switchInterface(address)` - 切换网络接口（会清空用户列表并重新广播）
- `loadInterfaceFromSettings()` - 从设置中加载保存的网络接口配置
- `isVirtualInterface(name, address)` - 检测网卡名称和 IP 判断是否为虚拟网卡

**自动接受机制**：
- 收到 `FILE_NOTIFY` 后自动创建传输记录和消息
- 自动回复 `FILE_ACCEPT`，无需用户确认
- 图片和文件均自动接收

#### `src/main/network/TcpTransferService.ts` - TCP 文件传输服务

**职责**：
- TCP 服务器启动和端口管理（动态分配 2426-2499）
- 文件分块传输（支持自适应分块大小）
- 传输进度跟踪和回调通知
- MD5 校验确保文件完整性
- 发送方和接收方状态管理

**TCP 帧协议**（长度前缀 + JSON）：
```typescript
interface TcpFrame {
  type: 'HANDSHAKE' | 'HANDSHAKE_OK' | 'CHUNK' | 'CHUNK_END' | 'TRANSFER_DONE' | 'TRANSFER_ERROR' | 'CANCEL'
  transferId?: string    // 传输唯一标识
  offset?: number        // 文件偏移量（断点续传预留）
  fileMd5?: string       // 文件 MD5 校验值
  seq?: number           // 分块序号
  data?: string          // Base64 编码的分块数据
  totalSize?: number     // 文件总大小
  reason?: string        // 错误原因
}
```

**分块大小策略**：
| 文件大小 | 分块大小 | 说明 |
|---------|---------|------|
| < 1MB | 128KB | 小文件快速传输 |
| 1-100MB | 512KB | 中等文件平衡传输 |
| > 100MB | 1MB | 大文件高效传输 |

**传输状态**：
```typescript
type TransferStatus = 'pending' | 'transferring' | 'completed' | 'failed' | 'rejected' | 'cancelled'
```

**公开方法**：
- `startServer()` - 启动 TCP 服务器，返回实际监听端口
- `sendFile(targetIp, targetPort, filePath, peerId, transferId, resumeOffset?)` - 发送文件
- `addTransfer(transfer)` - 添加传输记录
- `getTransfer(transferId)` - 获取传输记录
- `cancelTransfer(transferId)` - 取消传输
- `setCallbacks(onProgress, onComplete)` - 设置进度和完成回调
- `getDownloadPath()` - 获取下载目录路径

#### `src/renderer/src/store/messageStore.ts` - 消息状态

**状态结构**：
```typescript
interface MessageStore {
  conversations: Conversation[]     // 会话列表
  messages: Record<string, Message[]> // 按会话ID组织的消息列表
  currentConversationId: string | null  // 当前会话ID
  isLoading: boolean              // 加载状态
}
```

**Actions**：
- `loadConversations()` - 加载会话列表
- `loadMessages(conversationId, limit)` - 加载消息历史（合并到现有消息）
- `addMessage(message)` - 添加消息
- `sendMessage(conversationId, content, contentType)` - 发送消息
- `recallMessage(messageId, conversationId)` - 撤回消息
- `updateMessageStatus(messageId, status)` - 更新消息状态
- `setCurrentConversation(conversationId)` - 设置当前会话
- `createConversation(targetId, type, targetInfo)` - 创建会话（支持传递目标用户信息）
- `deleteConversation(conversationId)` - 删除会话及所有消息
- `markAsRead(conversationId)` - 标记已读

**事件监听**：
- `msg:receive` - 收到新消息（包含 isNewConversation 标志，用于自动创建新会话）
- `msg:ack` - 消息送达确认
- `msg:withdrawn` - 消息被撤回

**新会话处理逻辑**：
当收到消息时，如果 `msg:receive` 事件的 `isNewConversation` 为 true，Store 会自动：
1. 检查会话是否已存在
2. 如果不存在，创建新会话并添加到列表头部

## 4. 数据流

### 4.1 消息发送流程

```
渲染进程 (React)
    │
    │  window.electronAPI.invoke('message:send', data)
    ▼
预加载脚本 (preload)
    │
    │  ipcRenderer.invoke(channel, data)
    ▼
主进程 (main)
    │
    │  1. networkService.sendMessage(data) - 保存到数据库
    │  2. UDP 广播发送
    ▼
NetworkService
    │
    │  UDP 广播到 <动态计算的子网广播地址>:2425
    ▼
目标用户
```

**发送消息关键逻辑**：
1. 渲染进程调用 `message:send` IPC
2. 主进程先查找/创建对应会话（确保 FOREIGN KEY 约束）
3. 保存消息到本地数据库
4. 通过 UDP 广播发送消息
5. 渲染进程收到 `msg:ack` 更新消息状态

---

### 4.2 文件传输流程

#### 4.2.1 发送方流程

```
渲染进程 (React)
    │
    │  1. 创建临时消息（fileId = temp-${timestamp}）
    │  2. window.electronAPI.invoke('file:send', { to, filePath })
    ▼
主进程 (main)
    │
    │  networkService.sendFile(to, filePath)
    │  ├── 1. 计算文件 MD5
    │  ├── 2. 保存文件记录到数据库（status: pending）
    │  ├── 3. 创建传输记录到 TcpTransferService
    │  ├── 4. 发送 FILE_NOTIFY UDP 广播（含本机 TCP 端口）
    │  └── 5. 返回 transferId
    ▼
等待接收方响应...
    │
    │  收到 FILE_ACCEPT（含接收方 TCP 端口）
    ▼
TcpTransferService
    │
    │  sendFile(targetIp, targetPort, filePath, ...)
    │  ├── 1. 连接到接收方 TCP 端口
    │  ├── 2. 发送 HANDSHAKE 帧
    │  ├── 3. 分块读取文件并发送 CHUNK 帧
    │  ├── 4. 发送 CHUNK_END 帧（含 MD5）
    │  └── 5. 等待 TRANSFER_DONE 确认
    ▼
渲染进程
    │
    │  监听 file:progress 和 file:complete 事件
    │  更新消息状态和进度
```

#### 4.2.2 接收方流程（自动接受）

```
NetworkService
    │
    │  收到 FILE_NOTIFY UDP 包
    │  ├── 1. 自动创建文件记录（direction: receive）
    │  ├── 2. 自动创建传输记录到 TcpTransferService
    │  ├── 3. 自动创建消息记录到数据库
    │  └── 4. 自动发送 FILE_ACCEPT UDP 包（含本机 TCP 端口）
    ▼
TcpTransferService (TCP Server)
    │
    │  收到发送方 TCP 连接
    │  ├── 1. 解析 HANDSHAKE 帧
    │  ├── 2. 发送 HANDSHAKE_OK 确认
    │  ├── 3. 接收 CHUNK 帧并写入文件
    │  ├── 4. 更新进度（notifyProgress）
    │  ├── 5. 接收 CHUNK_END 帧
    │  ├── 6. 计算文件 MD5 并校验
    │  ├── 7. 发送 TRANSFER_DONE 确认
    │  └── 8. 更新数据库状态为 completed
    ▼
渲染进程
    │
    │  监听 file:progress 和 file:complete 事件
    │  更新消息状态和进度（渐变色进度条）
```

**关键设计点**：
1. **自动接受**：收到 FILE_NOTIFY 后自动接受，无需用户确认
2. **TCP 传输**：实际文件数据通过 TCP 传输，端口动态分配（2426-2499）
3. **分块策略**：根据文件大小自适应选择分块大小（128KB/512KB/1MB）
4. **进度通知**：通过 `file:progress` 和 `file:complete` 事件实时更新 UI
5. **进度条样式**：绿色渐变（传输中）、绿色完成（100%）、红色（失败）
6. **MD5 校验**：传输完成后校验文件完整性

### 4.3 消息接收流程

```
NetworkService
    │
    │  收到 UDP 数据包
    ▼
解析数据包 → 判断 type
    │
    ├── TEXT → handleTextMessage()
    │         │
    │         ├── 1. 保存用户信息 (databaseService.saveUser)
    │         ├── 2. 查找/创建会话 (databaseService.getConversationByTarget / createConversation)
    │         ├── 3. 更新会话联系人信息（最新发消息用户）
    │         ├── 4. 保存消息到数据库 (databaseService.saveMessage)
    │         ├── 5. 发送事件到渲染进程
    │         │    ├── 'msg:receive' (包含 isNewConversation 标志)
    │         │    └── 'conversation:new' (如有必要)
    │
    └── TEXT_ACK → mainWindow.webContents.send('msg:ack')
           │
           ▼
渲染进程 (messageStore.msg:receive / updateMessageStatus)
    │
    ▼
如 isNewConversation=true，自动添加新会话到列表
```

### 4.4 状态更新流程

```
主进程事件（用户上线/下线/消息到达）
    │
    ▼
webContents.send() → 预加载脚本
    │
    ▼
window.electronAPI.on() → Zustand Store
    │
    ▼
React 组件自动重新渲染
```

## 8. 注意事项

1. **安全性**：所有 IPC 通信必须经过 preload 脚本的白名单验证
2. **类型安全**：主进程和渲染进程共享类型定义在 `preload/index.ts`
3. **状态管理**：渲染进程状态存储在 Zustand 中，主进程数据通过 IPC 同步
4. **网络协议**：UDP 广播使用固定端口 2425，协议版本为 1；广播地址根据本机网络接口动态计算（IP | ~netmask），支持跨网段发现
5. **窗口控制**：按钮区域必须使用 `.no-drag` 类避免拖拽冲突
6. **FOREIGN KEY 约束**：发送消息时必须先确保会话存在，再保存消息
7. **消息合并**：加载消息时采用合并策略，避免丢失临时消息或切换会话时的数据
8. **新会话通知**：收到消息时通过 `isNewConversation` 标志自动处理新会话创建
9. **文件自动接受**：图片和文件均自动接受，无需 `file:accept` 确认
10. **文件拖拽/粘贴**：使用 `webUtils.getPathForFile()` 获取文件绝对路径
11. **进度条样式**：传输进度使用渐变色进度条（绿色：进行中/完成，红色：失败）
