# CubicleChat 需求文档

**项目名称**：CubicleChat  
**项目类型**：跨平台桌面应用（局域网即时通讯工具）  
**版本**：v1.0  
**日期**：2026-04-17  
**状态**：待开发

---

## 1. 项目概述

### 1.1 产品定位

CubicleChat 是一款面向企业内网/局域网环境的即时通讯工具，**无需服务器部署、无需互联网，开箱即用**。用户只需在同一 Wi-Fi 或有线局域网内，即可自动发现彼此并开始通讯。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 零服务器依赖 | 所有通信在局域网内点对点完成，无中心节点 |
| 轻量快速 | 安装包 < 80 MB，启动时间 < 2 秒 |
| 数据本地存储 | 所有历史消息与文件元数据存储于本机 SQLite |
| 跨平台一致性 | Windows、macOS、Linux 界面与体验一致 |

### 1.3 目标平台

| 平台 | 最低版本 | 架构 |
|------|---------|------|
| Windows | Windows 10 (1903+) | x64 |
| macOS | macOS 11 (Big Sur)+ | x64 / ARM64 (Apple Silicon) |
| Linux | Ubuntu 20.04 / CentOS 8 / Debian 11 | x64 |

### 1.4 目标用户

| 用户类型 | 典型场景 |
|---------|---------|
| 小型办公团队 | 日常工作沟通，替代微信/钉钉等需要互联网的工具 |
| 工厂/制造业 | 封闭内网环境下的跨部门沟通 |
| 学校/实验室 | 局域网内文件共享与即时沟通 |
| 保密要求高的单位 | 数据不出内网，合规要求满足 |

## 2. 功能需求

### 2.1 用户发现与管理

#### F-01 局域网自动发现
- **描述**：程序启动后，自动向局域网广播"上线"信号，同时监听其他用户的广播
- **触发条件**：应用启动时、网络接口变更时
- **广播周期**：每 30 秒发送一次心跳广播
- **下线检测**：超过 90 秒未收到心跳，标记用户为离线
- **验收标准**：同局域网内的用户在 10 秒内出现在在线列表中

#### F-02 用户信息设置
- **昵称**：必填，长度 2-20 字符，默认值为主机名
- **头像**：可选，从 40 个内置 emoji 头像中选择（动物、职业、虚拟角色等），默认使用昵称首字母
- **验收标准**：更改昵称或头像后，其他在线用户在 30 秒内看到更新

#### F-03 在线状态显示
- 状态列表：在线（绿）、忙碌（黄）、离开（灰）、隐身（对外显示离线）
- 状态可手动切换，不影响消息接收能力（除隐身外）

#### F-04 用户分组
- 支持将用户加入自定义分组（如：研发组、运营组）
- 分组数据存储于本地，不同步至其他用户

---

### 2.2 即时消息

#### F-05 单聊（一对一）
- **文本消息**：支持 UTF-8 全字符，单条最大 4096 字节
- **表情**：支持 Unicode Emoji，内置常用表情面板
- **消息撤回**：发送后 2 分钟内可撤回，对方显示"[消息已撤回]"
- **验收标准**：消息延迟 < 100ms（同局域网）

#### F-06 群聊
- **创建群组**：选择在线用户创建临时群组，广播通知成员
- **成员管理**：创建者可添加/移除成员
- **群消息**：支持文本、表情、文件（与单聊一致）
- **最大成员数**：50 人

#### F-07 消息通知
- 新消息时任务栏图标闪烁（Windows/macOS）/ 托盘图标动画（Linux）
- 系统通知包含：发送者昵称 + 消息前 30 字符
- 支持免打扰模式（按会话/全局）

#### F-08 历史消息
- 所有消息存储于本机 SQLite
- 支持按关键词搜索历史消息
- 历史消息默认保留 180 天，可在设置中修改（30-∞天）

---

### 2.3 文件与图片传输

#### F-09 图片发送
- **发送方式**：粘贴剪贴板图片、拖放图片文件、点击按钮选择
- **预览**：消息气泡中内嵌缩略图（最大 240×240 px）
- **原图查看**：双击图片打开大图查看器，支持缩放、拖拽移动
- **自动接受**：图片无需接收方确认，自动接收并显示
- **格式**：PNG、JPG、GIF、WebP，单张最大 20 MB

#### F-10 文件发送
- **发送方式**：拖放文件到输入框、粘贴文件、点击按钮选择
- **自动接受**：文件无需接收方确认，自动接收
- **进度显示**：渐变色进度条显示传输百分比和速度，完成显示绿色
- **断点续传**：传输中断后可从断点继续
- **大小限制**：单文件最大 2 GB

#### F-11 文件管理
- 已收/已发文件在"文件"面板中集中展示
- 支持按时间、大小排序
- 支持在文件管理器中打开文件所在目录

#### F-12 会话管理
- **删除会话**：右键会话列表项删除单个会话，确认后清空该会话聊天记录
- **清空列表**：右键会话列表空白处清空所有会话，确认后删除所有聊天记录

---

### 2.4 系统设置

#### F-12 应用设置

| 设置项 | 类型 | 默认值 | 说明 |
|-------|------|--------|------|
| 我的昵称 | 文本 | 主机名 | - |
| 头像 | 枚举 | 默认（首字母） | 从 40 个内置 emoji 头像中选择 |
| 文件接收目录 | 路径 | ~/Downloads/CubicleChat | - |
| 历史消息保留天数 | 数值 | 180 | 30~无限 |
| 开机自启 | 布尔 | false | 跨平台支持 |
| 最小化到托盘 | 布尔 | true | - |
| 语言 | 枚举 | 简体中文 | 简体中文/English |
| 主题 | 枚举 | 跟随系统 | 亮色/暗色/跟随系统 |
| UDP 广播端口 | 数值 | 2425 | 与飞秋兼容 |
| TCP 文件传输端口 | 数值 | 2426 | - |
| 网络接口 | 枚举 | 自动选择 | 多网卡时手动选择要使用的网卡 |
| 显示虚拟网卡 | 布尔 | false | 开启后在网卡列表显示虚拟网卡（VMware/Docker/VPN 等） |

#### F-13 数据管理
- 清空历史消息（按对话/全部）
- 导出聊天记录（JSON / TXT 格式）
- 数据库压缩（VACUUM）

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 要求 |
|------|------|
| 消息发送延迟 | < 100 ms（局域网 1Gbps 环境） |
| 应用启动时间 | < 2 秒（冷启动） |
| 内存占用 | 空闲时 < 80 MB |
| CPU 占用 | 空闲时 < 1%，消息处理时 < 5% |
| 文件传输速度 | 不低于网络带宽的 80% |
| 最大在线用户 | 支持同局域网 200 个用户并发在线 |

### 3.2 可靠性需求

| 指标 | 要求 |
|------|------|
| 消息可靠投递 | 单聊消息有确认机制，超时重试 3 次 |
| 数据不丢失 | SQLite WAL 模式，写入即持久化 |
| 异常恢复 | 崩溃后重启自动恢复所有会话状态 |

### 3.3 安全需求

- **传输加密**：v1.0 不加密（局域网可信环境），v1.1 规划 AES-256 加密
- **本地数据**：SQLite 数据库不加密（v1.0），后续支持加密存储

## 4. 用户故事

### Epic 1: 快速上手

```
作为 新用户
我希望 启动程序后立即看到局域网内的其他用户
以便 无需任何配置即可开始聊天
```

**验收标准（AC）：**
- AC1: 首次启动后 10 秒内在线列表自动填充（若有其他在线用户）
- AC2: 不需要注册账号、不需要输入服务器地址
- AC3: 默认昵称自动设置为主机名，可随时更改

### Epic 2: 日常沟通

```
作为 团队成员
我希望 快速发送文本消息和图片给同事
以便 替代微信等需要翻墙或泄露隐私的工具
```

**验收标准（AC）：**
- AC1: Enter 发送消息，Shift+Enter 换行
- AC2: 粘贴截图后立即显示缩略图预览，再次 Enter 确认发送
- AC3: 消息在对方屏幕上显示时间戳

### Epic 3: 文件共享

```
作为 团队成员
我希望 向同事发送大文件（如设计稿、报告）
以便 不依赖 U 盘或公司网盘即可快速传输
```

**验收标准（AC）：**
- AC1: 拖放文件到聊天窗口即可发起传输
- AC2: 实时显示传输进度条和速度
- AC3: 传输中断后可以续传，不需要重新发送整个文件

### Epic 4: 群组协作

```
作为 项目负责人
我希望 创建一个包含项目成员的群组
以便 可以群发通知和分享文件
```

**验收标准（AC）：**
- AC1: 从在线用户列表中多选创建群组，输入群名称
- AC2: 被邀请成员收到入群通知
- AC3: 群消息历史可本地搜索

## 5. 约束与假设

### 5.1 约束

1. **网络环境**：用户必须在同一局域网子网（或通过路由器能互通的网段）内
2. **单点**：v1.0 不支持离线消息——发送消息时接收方必须在线
3. **无服务器**：不依赖任何云服务或中心服务器

### 5.2 假设

1. 局域网内 UDP 广播不被防火墙或交换机阻断
2. 用户设备时钟误差不超过 60 秒（用于消息排序）
3. 同一台机器同时只运行一个 CubicleChat 实例
