## 1. 技术选型

### 1.1 选型决策矩阵

| 层次 | 候选方案 | 选定方案 | 选定理由 |
|------|---------|---------|---------|
| 应用框架 | Electron / Tauri / Qt | **Electron** | 跨平台成熟度最高，生态最丰富，Web 技术栈开发效率高 |
| 前端框架 | React / Vue / Svelte | **React 18** | 组件生态完善，TypeScript 支持一流，团队熟悉度高 |
| 状态管理 | Redux / Zustand / Jotai | **Zustand** | 轻量无模板代码，适合中型应用，TypeScript 友好 |
| 样式方案 | CSS Modules / Tailwind / Emotion | **Tailwind CSS v3** | 工具类优先，设计系统统一，构建产物小 |
| 数据库 | SQLite / IndexedDB / LevelDB | **better-sqlite3** | 同步 API 简洁，性能优秀，与 Electron 主进程完美集成 |
| ORM | Drizzle / Prisma / Knex | **Drizzle ORM** | 轻量零依赖，SQL-like API，与 SQLite 无缝配合 |
| 构建工具 | webpack / Vite / esbuild | **Vite + electron-vite** | 开发热重载快，生产构建体积小 |
| 打包工具 | electron-builder | **electron-builder** | 支持 Windows NSIS + ZIP，Linux AppImage + deb |
| 语言 | JavaScript / TypeScript | **TypeScript 5** | 全栈类型安全，减少运行时错误 |

### 2.2 IPC 通信架构

主进程与渲染进程通过 Electron IPC（Inter-Process Communication）通信：

```
渲染进程                          主进程
   │                               │
   │  ipcRenderer.invoke(channel)  │
   │──────────────────────────────►│
   │                               │  处理请求
   │         Promise<result>       │
   │◄──────────────────────────────│
   │                               │
   │  ipcMain.on(event, data)      │
   │◄──────────────────────────────│  主动推送事件
   │                               │  (新消息、用户上线等)
```

**IPC Channel 规范：**

| Channel | 方向 | 描述 |
|---------|------|------|
| `msg:send` | 渲染→主 | 发送消息 |
| `msg:receive` | 主→渲染 | 收到新消息推送 |
| `user:online` | 主→渲染 | 用户上线通知 |
| `user:offline` | 主→渲染 | 用户离线通知 |
| `file:send` | 渲染→主 | 发起文件传输 |
| `file:progress` | 主→渲染 | 文件传输进度 |
| `db:query` | 渲染→主 | 数据库查询 |
| `settings:get` | 渲染→主 | 读取设置 |
| `settings:set` | 渲染→主 | 保存设置 |

### 3.2 服务层设计

遵循**三层架构**（参见全栈开发规范）：

```
IPC Handler → Service → Repository → Database
     ↕                                  ↕
  网络事件                            SQLite
```

**各层职责：**

| 层次 | 职责 | 禁止事项 |
|------|------|---------|
| IPC Handler | 参数校验、调用 Service、格式化响应 | 包含业务逻辑 |
| Service | 业务规则、编排多个 Repository 调用 | 直接访问数据库 |
| Repository | SQL 查询、数据映射 | 包含业务逻辑 |

## 4. 数据流

### 4.1 发送消息流程

```
用户输入 Enter
    │
    ▼
[Renderer] MessageInput.tsx
    │ ipcRenderer.invoke('msg:send', {to, content})
    ▼
[Main] message.ipc.ts (参数验证)
    │
    ▼
[Main] MessageService.send()
    ├─ MessageRepo.save() → SQLite (写入本地)
    └─ UdpMessenger.send() → UDP Socket → 目标 IP:Port
                                               │
                                               ▼
                                          [对方 Main]
                                          UdpMessenger.onReceive()
                                               │
                                               ▼
                                          MessageService.receive()
                                               ├─ MessageRepo.save() → SQLite
                                               └─ ipcMain.emit('msg:receive', data)
                                                        │
                                                        ▼
                                                  [对方 Renderer]
                                                  更新 messageStore
                                                  渲染新消息气泡
```

### 4.2 文件传输流程

```
拖放文件
    │
    ▼
[Renderer] DropZone 组件
    │ ipcRenderer.invoke('file:send', {to, filePath})
    ▼
[Main] FileService.initTransfer()
    ├─ 读取文件元信息（大小、名称、MD5）
    ├─ 通过 UDP 发送文件请求通知
    └─ 等待对方 TCP 连接
         │
         ▼ (对方接受)
    [Main] TcpTransfer.startSend()
         ├─ 建立 TCP 连接
         ├─ 分块发送（512KB/块）
         └─ ipcMain.emit('file:progress', {percent, speed})
              │
              ▼
         [Renderer] 更新进度条
```

### 5.1 路径处理

使用 Node.js `path` 模块统一处理路径，避免分隔符差异：

```typescript
import { app } from 'electron';
import path from 'path';

// 用户数据目录
const userDataPath = app.getPath('userData');
// Windows: C:\Users\<user>\AppData\Roaming\CubicleChat
// Linux:   /home/<user>/.config/CubicleChat

// 数据库文件
const dbPath = path.join(userDataPath, 'cubicle.db');

// 文件接收目录
const downloadPath = path.join(app.getPath('downloads'), 'CubicleChat');
```

## 6. 安全架构

### 6.1 Electron 安全配置

```typescript
// 主窗口配置（安全优先）
new BrowserWindow({
  webPreferences: {
    nodeIntegration: false,        // 禁止渲染进程直接访问 Node
    contextIsolation: true,        // 启用上下文隔离
    sandbox: true,                  // 启用沙箱
    preload: path.join(__dirname, 'preload.js'),
  },
});
```

### 6.2 Preload 安全边界

```typescript
// preload/index.ts — 仅暴露必要 API
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('ipc', {
  send: (channel: string, data: unknown) => {
    const allowed = ['msg:send', 'file:send', 'settings:set'];
    if (allowed.includes(channel)) ipcRenderer.invoke(channel, data);
  },
  on: (channel: string, callback: Function) => {
    const allowed = ['msg:receive', 'user:online', 'user:offline', 'file:progress'];
    if (allowed.includes(channel)) {
      ipcRenderer.on(channel, (_, ...args) => callback(...args));
    }
  },
});
```

## 7. 性能优化策略

| 场景 | 策略 |
|------|------|
| 历史消息加载 | 虚拟滚动（react-window），每次渲染 50 条 |
| 大量在线用户 | 在线用户列表按字母分组，懒加载分组 |
| 图片缩略图 | 主进程生成缩略图缓存，渲染进程只显示缩略图 |
| 频繁 IPC 调用 | 批量合并 IPC 调用，减少进程切换开销 |
| 数据库写入 | WAL 模式 + 批量写入（消息队列缓冲 100ms） |
| 内存泄漏防护 | 聊天记录超过 500 条时从内存中清除早期消息 |
